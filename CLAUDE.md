# sex (and sex-lite)

Firecrawl v2 compatible web search (SearXNG) + fetch (Defuddle) as a CLI, HTTP API (Hono + oRPC) and MCP server (`@modelcontextprotocol/server` v2). See README.md for usage.

## Layout

A Bun workspace (`linker = "hoisted"` in bunfig.toml: one root `node_modules`, which the sex build walks) with three packages:

- `packages/core` (`@sex/core`, imported as `@sex/core/<file>.ts`, tests' helpers as `@sex/core/test/helpers.ts`) — what both products share: search, fetch + extraction, SSRF guard, config, errors, and the HTTP / MCP / CLI scaffolding. Must not import from `sex` or `sex-lite`, nor depend on browser, LLM, here-docs or job code.
- `packages/sex` — the full product: core plus browser, LLM, here-docs, map / crawl / batch / extract and jobs.
- `packages/sex-lite` — search + fetch only (`src/cli.ts`, `src/server.ts` for the HTTP app and its two MCP tools, `src/engine.ts` for `liteEngine`, which is a `BaseEngine` whose 501 hints point at sex). Keep it to core plus wiring; a feature that needs more belongs in sex.

Files:

- `packages/core/src/engine.ts` — `BaseEngine`: SearXNG, extract pool, scrape limit, `scrape` / `search` / `warmup` / `describe` / `close`. sex's `Engine` (`packages/sex/src/engine/engine.ts`) extends it and overrides `browser` / `llm` / `docs`.
- `packages/core/src/capabilities.ts` — the interfaces a scrape uses for the optional capabilities (`ScrapeBrowser`, `ScrapeLlm`, `ScrapeDocs`, `ScrapeCache`, `ChangeTracker`) and `GUARD_MAX_CHARS`. `scrapeUrl` / `search` take a `ScrapeContext` / `SearchContext` (any `BaseEngine`), never sex's `Engine`; a capability is used only when present and `enabled`, otherwise `browserRequired()` / `llmRequired()` with the context's `missingHints`.
- `packages/core/src/cli/common.ts` — flags (`coreArgs`, `httpArgs`, `searchArgs`, `fetchArgs`), `coreOverrides`, `runSearch` / `runFetch`, `engineOrExit`, `warmupOrExit`, `onShutdown`, `listenAddress`. `packages/sex/src/cli.ts` and `packages/sex-lite/src/cli.ts` are citty CLIs (`search`, `fetch`, `serve`, alias `http`) built from them. There is no separate worker process: sex's `serve` runs crawl/batch/extract tasks itself.
- `packages/core/src/config.ts` — zod-validated `CoreConfig` (`resolveCoreConfig`, plus `CORE_FIELDS` / `parseFields` / `coreConfigFrom` for products that add settings); `packages/sex/src/config.ts` extends it (`resolveConfig`; `SEX_WEBHOOK_SECRET` has no CLI flag, so the key stays out of the process list). Precedence: CLI flag → `SEX_*` env → default (sex-lite reads the same `SEX_*` names; `SEX_PROXY_URL` is env only, like `SEX_WEBHOOK_SECRET`, and `parseFields` never echoes it back). Empty values count as unset; invalid values throw `CONFIG_INVALID`. Tests pass an explicit env object instead of `process.env`.
- `packages/core/src/errors.ts` — the `ERRORS` catalog (every error code with its HTTP `status`, `retryable` and `fallback`) and `AppError`, which takes its status and hints from it: `new AppError("CODE", message, details?)`. New codes go in the catalog first. Deterministic failures are never 502/503 (the SDK retries those); only `*_UNAVAILABLE` and upstream errors (`LLM_ERROR`, `SEARCH_BACKEND_ERROR`) are. An LLM endpoint's 4xx (bad key, wrong model) is `LLM_REQUEST_REJECTED` (500). `fallback` says whether a failed browser scrape may be answered over plain HTTP: `scrapeInner` does that (sequentially, within the scrape's remaining deadline, at least `FALLBACK_MIN_MS`; never with actions) and also when the browser renders a 2xx page with empty markdown; the document's `warning` says so. Helpers: `badRequest`, `unsupported`, `browserRequired`, `llmRequired`. Throw these, not plain `Error`s.
- `packages/core/src/log.ts` — leveled logger, stderr only.
- `packages/sex/src/engine/` — sex's engine on top of core (map, crawl, batch, extract, browser, llm, docs, jobs)
- `packages/core/src/deadline.ts` — `Deadline`: the time one operation (scrape, search, map) has left plus the caller's cancellation. Created once at the top (`Deadline.start(ms, { signal })`, or `Deadline.unbounded(signal)` for jobs) and passed down; steps use `signal`, `remaining()`, `slice(ms)` for a step budget of their own, `sleep`, `bound(promise)` for work that ignores the signal, and `translate(err)`, which turns anything thrown after the abort into `SCRAPE_TIMEOUT` (time ran out) or `TIMEOUT` (caller cancelled). Never build `AbortSignal.timeout` / `AbortSignal.any` in a step. `scrapeUrl` cuts `timeout` for the whole scrape (fetching, rendering, extracting and the LLM calls; no `timeout` with LLM formats or the guard means `max(SEX_TIMEOUT, 60 s)`, see `scrapeTimeout`); each LLM call gets `min(SEX_LLM_TIMEOUT, what is left)`. Extract jobs scrape with `llmOutsideTimeout`, so their guard calls are cut from the job's deadline instead.
- `packages/core/src/markdown-html.ts` — `markdownToHtml`: `html` / `rawHtml` of a converted document (PDF, office file, CSV) is its Markdown through `Bun.markdown.html` (raw HTML escaped via `noHtmlBlocks` / `noHtmlSpans`); no Markdown library. `packages/core/src/pdf.ts` extracts page by page and stops at `maxPages` (`numPages` = extracted, `totalPages` = in the file; the docs path reports the same pair). Both paths return the pages one by one (`PdfText.pages` / `DocsResult.pages`, `PdfPage`), and `scrapeInner` builds `Document.pages` (`parsers[].pages`) and the `pageMarkers` text from them with `joinPages`; a converter that returns text belonging to no page gets `pages: undefined` and a warning instead. `mode` / `blocks` / `refresh` are still ignored (here-docs does not say which pages it OCR'd, nor take an OCR switch).
- Options that cannot be honoured are refused or reported, never dropped: `assertSupportedOptions` (501 for `redactPII` / `zeroDataRetention` / `onlyCleanContent`, 404 `SCRAPE_NO_CACHED_DATA` for `lockdown` / `minAge`, 400 for `rawBase64` combinations and `fastMode` + actions) and `ignoredOptionWarnings` (Firecrawl's "-- your scrape may be partial") in `scrape.ts`; search does the same for `tbs` / `country` / `location` in `search.ts`. A new option that has no effect goes into one of those two, and into the README's differences list. `rawBase64` returns before the browser and extraction (`safeFetch` only); `fastMode` makes `scrapeInner` treat the browser as absent. `SEX_STRICT_REQUESTS` (`strictRequests`) makes `procedureBase` reject undeclared body fields (nested objects too) with 400; MCP is not covered.
- `packages/core/src/net.ts` — `networkError(err, url)` names a failed fetch (Bun/Node `code`, Chromium `net::ERR_*`, Lightpanda's libcurl names) as `SCRAPE_DNS_RESOLUTION_ERROR` / `SCRAPE_SSL_ERROR` / `SCRAPE_SITE_ERROR` / `FETCH_FAILED`; `safeFetch` and the browser both use it. SSRF guard: `isPrivateIp` / `resolvePublicAddresses` / `assertPublicUrl` (ipaddr.js). `safeFetch` re-checks every redirect hop and connects to the DNS-validated IP (`pinToAddress`) so a second lookup cannot rebind. `FetchOptions.proxy` (`config.proxyUrl`, `SEX_PROXY_URL`) is a required field, so a new call site must decide: with a proxy the request goes through Bun `fetch`'s `proxy` option and is **not pinned** (the proxy resolves the name); the host is still resolved and checked before every hop, and a name that does not resolve locally is refused (`requireResolvable`, also passed by the browser `requestGuard`), since the proxy's resolver could know an internal name. Caller-set `Proxy-Authorization` / `Proxy-Connection` are dropped. Rebinding between check and the proxy's lookup is the proxy's to stop (README, "出站代理"); never claim pinning for proxied requests. The proxy URL carries credentials: no CLI flag, redacted in config errors and in the logged Lightpanda argv (`redactArgv`).
- `packages/core/src/extract-pool.ts` + `packages/core/src/extract-worker.ts` — HTML/PDF extraction in a worker-thread pool (`SEX_EXTRACT_WORKERS`, 0 = main thread). `bun run build` embeds the worker as an extra entrypoint.
- `packages/sex/src/engine/crawl.ts` `crawlParamsFromPrompt` maps the site first (`mapSite` with the sex-only `skipSearch`, `filterByPath: false`, limit 50, 15 s) and gives the URLs to `crawlOptions` as `site_urls`; a failed map or a start URL alone means the prompt alone. Its tokens are not counted (a crawl job does not exist yet, and has no `tokensUsed`).
- `packages/sex/src/engine/url-filter.ts` — include/exclude regex compilation (ReDoS heuristic, length/count limits, 2048-char match cap), `isSkippableFile` (non-page extensions) and `basePathOf`; shared by crawl and map.
- `packages/core/src/rewrite.ts` — `rewriteUrl` (Google Docs/Sheets/Slides/Drive links → export URLs; pure, runs in `scrapeUrl` before `assertPublicUrl` so the fetched URL is the one checked) and `fileKindOf` (documents/images by extension, which skip the browser).
- `packages/core/src/scrape.ts` `cachePlan` + `packages/sex/src/engine/cache.ts` — the page cache (`maxAge` / `storeInCache` / `minAge` / `lockdown`, `metadata.cacheState` / `cachedAt`). `scrapeUrl` decides, through the `ScrapeCache` interface only; sex-lite has none (then `lockdown` / `minAge` are 404s). It caches what was fetched (HTTP body, or the browser's rendered HTML as UTF-8), not the Document: a hit takes the place of `fetchBody` (like `upload`) and the browser is skipped, so formats, selectors, `parsers` and LLM options are applied on top and are not in the key (`CacheKey.variant` has render mode, `blockAds`, `waitFor`, `mobile`, `skipTlsVerification`, languages). `maxAge: 0` (explicit) skips the read but still stores (refresh); a request without `maxAge` on a server whose default is 0 uses the cache not at all. Never cached or read: actions, `headers`, `rawBase64`, uploads, non-2xx, a browser fallback's or empty page. A new option that changes the fetched bytes goes into `variant`. `SqliteScrapeCache` is `<dataDir>/cache.sqlite` (own file, zstd bodies, `user_version` mismatch or a broken file = recreate; no data dir = no cache): `SEX_CACHE_TTL_MS` expiry (also the ceiling for `maxAge`), `SEX_CACHE_MAX_BYTES` evicts least recently used, `SEX_CACHE_MAX_AGE_MS` (default 0) is the `maxAge` of a request without one. It is not `DocumentLog` (that appends per job and only drops whole jobs) and not `jobs.sqlite`. changeTracking uses a different store (below).
- `packages/core/src/change-tracking.ts` + `packages/sex/src/engine/change-tracker.ts` — the `changeTracking` format. Core owns the rules (`trackChanges`, called by `scrapeInner` after the LLM formats; `sameContent` is deliberately stricter than Firecrawl's (which compares character counts, so a moved paragraph or a same-length edit is "same"): `[iframe](…)` removed and whitespace runs collapsed, then the text must be equal; 404 = `removed`; only a 2xx page is stored, after the comparison; a store that cannot be read or written is a `warning`, never a failed scrape) and talks to the `ChangeTracker` interface only (`get` / `put` / `diff`); `ctx.changeTracker` absent = `unsupported(…, missingHints.changeTracking)` 501 (sex-lite's hint names sex; sex without a data dir gets `CHANGE_TRACKING_HINT`). `SqliteChangeTracker` is `<dataDir>/change-tracking.sqlite`: one row per `(url, tag)` (null tag and "" are the same, stored as ""), zstd markdown, replaced by the next scrape, never expired or evicted, and a file that will not open is an error, not recreated (it is the only copy; a `user_version` newer than ours is refused, an older one must migrate, not drop). Not `SqliteScrapeCache` (expires, evicts, recreates). `diff` is `change-diff.ts` (`markdownDiff`): the `diff` package (jsdiff, sex only; core must not import it, hence the interface method) `structuredPatch` → Firecrawl's `{ files: [{ from, to, chunks: [{ content, changes }] }] }` + `formatPatch` text, capped at 5 s (jsdiff is synchronous), then skipped with a warning. `json` mode needs the LLM: with a `schema` `extractJson` runs on both versions and `compareExtracted` diffs the top-level fields; without one `ScrapeLlm.describeChanges` (`CHANGES_SYSTEM` / `changesUser` in `prompts.ts`, each version gets half of `maxInputChars`). With `checkPromptInjection` the stored version is scanned too (a stored version that is flagged skips `json` with a warning instead of failing, so it can still be replaced). `visibility` is always `visible` (no crawl scoping). Uploads are a 400.
- `packages/sex/src/engine/docs.ts` — `DocsConverter`: PDFs, office documents and images through here-docs (`--docs` / `SEX_DOCS`). One engine per process, started by `serve` warmup (or on first use), run on the main thread (the native engines do not block the event loop). `convertPages` is iterated so `parsers[].maxPages` stops early; the scrape's `Deadline` aborts it. `pLimit(SEX_DOCS_CONCURRENCY)` (default `min(2, cores-1)`; light-ocr has one recognition thread per engine, so more only queues pages) bounds simultaneous conversions, and the wait for a slot is inside the deadline. Conversion gets 90% of what is left; if that runs out after some pages, those are returned with a `timeout` warning, with none it is `SCRAPE_TIMEOUT`. Off: PDFs go through unpdf in the extract pool, other files are 415.
- `packages/sex/src/engine/llm.ts` — LLM client on xsai (`chat` adapter + `generateText`): `SEX_LLM_SMALL_MODEL` (`config.llm.smallModel`, same endpoint and key; falls back to the main model) serves the auxiliary calls, which pass `small: true` to `completeJson` / `complete`: `planExtract`, `generateSchema`, `crawlOptions` and `selectLinks`; extraction, summary, question, highlights and the prompt injection guard stay on the main model (the guard is a security check: never trade its detection rate for cost; a new auxiliary call decides which side it is on). checks result `status`/`reason`/refusals, narrows errors with `isInstance`, retries 429 per `retry-after` within `SEX_LLM_TIMEOUT`. JSON replies that fail to parse or validate get one correction turn (`completeJson`). Also the line-selection highlights/directQuote (`selectLines` numbers the units `splitSegments` in `segments.ts` returns: a line, a whole code fence or table, a sentence of a long line, cut by `Intl.Segmenter`), `selectLinks` (the small-model pick among an extract `/*`'s mapped pages, by number, so it can only return candidates), the prompt injection guard (`checkPromptInjection`; `scrapeUrl` scans exactly the text it sends on, cut at `GUARD_MAX_CHARS` with a warning, and extract applies the same cut and collects page warnings into the job's `warning`) and the extract planning calls.
- `packages/sex/src/engine/prompts.ts` — every prompt text. Page content goes inside tags (`tagged`, escaped with `escapeTags`), each system prompt that sees page content ends with `untrustedNotice`, and reference material comes before the task. Add new prompts here, not inline.
- `packages/sex/src/engine/extract.ts` + `packages/sex/src/engine/extract-merge.ts` — Firecrawl's extract flow: a `/*` URL is expanded by `expandWildcard` (map up to 200 candidates, then `Llm.selectLinks` when there is a prompt; a failed or empty pick falls back to the map order with a warning), generate a schema for prompt-only requests, classify Single-Answer vs Multi-Entity, extract multi-entity keys per page with `is_content_relevant`, the rest from all pages together, and merge partial results in code (no LLM merge).
- `packages/sex/src/engine/json-schema.ts` — Ajv compile (400 on invalid schema) for user JSON Schemas; LLM JSON output is validated against the original schema, since xsai's strict `json_schema` drops keywords like `allOf`/`not`/`if`.
- `packages/core/src/page-script.js` — page-side extractor, imported as text. Runs inside the browser (injected next to Defuddle's bundle) and in Node (via `new Function` on a linkedom document). Keep it a single self-contained function expression. Extraction retries with the whole body when main-content detection finds under 20 words, and above `maxScoredElements` (30000) elements it skips Defuddle's selector removal, scoring, content patterns and standardizing and only converts the body; both add a `notes` entry, which `scrapeUrl` puts in `warning`. `packages/core/scripts/bench-extract.ts` measures Defuddle's stages and the fast path on synthetic big pages (`stages`, `compare`); rerun it before changing the limit.
- `packages/core/src/searxng.ts` — `SearxngService`: the external SearXNG at `SEX_SEARXNG_URL`, or else a SearXNG child process started with `startServer()` from `@searxng-js/searxng` (prebuilt Nuitka binary; `SEX_SEARXNG_PATH` / `SEX_SEARXNG_SETTINGS` override binary and settings.yml). Started lazily (`serve` warmup starts it up front), started again after it exits, cooldown after repeated failed starts (`SEARCH_BACKEND_UNAVAILABLE`). It exits when its stdin pipe closes, so it dies with sex even on SIGKILL. Search code gets the base URL from `engine.searxng.url()`, never from config.
- `packages/sex/src/engine/browser.ts` — `BrowserPool`: `scrape` takes the scrape's `Deadline` (waiting for a slot, load, `waitFor`, actions and the page script all run inside it; the page's context is closed when it ends). CDP connections to a Lightpanda child process (`--lightpanda`) or an external browser (`--cdp-url`). The child is spawned lazily, spawned again after it exits, and not respawned for a cooldown after repeated failed starts (`BROWSER_UNAVAILABLE`). On Linux with `setpriv` it runs as `setpriv --pdeathsig TERM -- lightpanda serve ...` so it dies with sex even on SIGKILL (no equivalent on macOS; plain spawn otherwise), and gets `--block-private-networks` unless private networks are allowed (and `--http-proxy <SEX_PROXY_URL>` when a proxy is set; credentials end up on its command line, it has no env or file alternative); an external `--cdp-url` browser gets `createBrowserContext({ proxyServer })` per page with the URL's credentials answered through `page.authenticate` (`contextProxy`) (a second line of defence behind the `requestGuard` interception, which stays primary because `--cdp-url` browsers have no such flag).
- `packages/sex/src/engine/browser-policy.ts` — request policy pipeline for the browser path. A `RequestPolicy` decides per request: continue, change headers, or abort; `RequestPolicyPipeline` runs them in order and interception is on only when one is active. `applyRequestPolicies(page, opts)` is the one place that sets user headers/cookies and attaches the handler: `PrivateNetworkPolicy` (the SSRF `requestGuard`; per-origin verdict cache, records refused main-frame navigations) and `OriginScopedCredentialsPolicy` (`Authorization` / `Proxy-Authorization` only on the target's origin; `Cookie` goes to the cookie jar as host-only cookies). New request behaviour is a new policy in the `policies` list of `applyRequestPolicies`, not code in `browser.ts`. `MediaBlockPolicy` (`SEX_BLOCK_MEDIA`: image / media resource types) and `AdBlockPolicy` (`blockAds`, below) come first, so a blocked request never costs the private-network policy a DNS lookup; both are `optional`: on a browser that cannot intercept they are dropped instead of failing the scrape (only the SSRF guard and credentials policies are safeguards). Neither ever blocks a main-frame navigation. `applyRequestPolicies` returns `adsBlocked()`, which `BrowserPool` puts in `BrowserScrapeResult.adsBlocked`. The handler never passes `cookie` back to the browser (Lightpanda 1.0.2 reports it one character short).
- `packages/sex/src/engine/adblock.ts` + `packages/sex/scripts/adblock.ts` — `blockAds` (request option, default true: `scrapeUrl` passes `options.blockAds ?? true`; browser only). The EasyList + EasyPrivacy domain table is derived by the script from a pinned easylist/easylist commit (`EASYLIST_COMMIT`) and checked against `ADBLOCK_TABLE_SHA256`; only `||domain^` (optionally `$third-party`) and `@@||domain^` rules are kept, as lines `domain` / `~domain` (third-party only) / `@domain` (exception). Like Lightpanda it is embedded zstd-compressed by `build.ts` (`registerEmbeddedAdblock`) and from source derived into `$XDG_CACHE_HOME/sex-build` on first use (a table that cannot be had logs a warning once and means no blocking). `loadAdBlockList()` parses it into three Sets on first use; `AdBlockList.blocks(host, pageSite)` walks the label suffixes, an exception winning over any block rule. New rule kinds (URL paths, wildcards, options) need a different matcher behind the same `AdBlockPolicy`, not more cases in the Sets. Upgrading: change `EASYLIST_COMMIT`, run `bun packages/sex/scripts/adblock.ts`, put the printed hash in `ADBLOCK_TABLE_SHA256`. EasyList is GPLv3 / CC BY-SA 3.0; the README names source and licence. `packages/sex/scripts/bench-adblock.ts` measures the cost against a real Lightpanda (`overhead`, `pages`, `cold`).
- `packages/sex/src/engine/jobs/scheduler.ts` — `JobScheduler` (`engine.jobs.scheduler`): the one way a task gets into the queue (never `queue.add` from a handler), and the place that decides order and pace. crawl-start / extract have no lane and are served before any lane; a page task waits in its job's lane (`Lane { id: jobId, cooldownMs }`); lanes are served in turn, so a big batch cannot starve a small job. `pageLimits(options)`: `maxConcurrency` caps the lane, `delay` makes the cap 1 and sets `cooldownMs`, the quiet time *after a page finished*. It never re-queues a task: the queue skips a capped or cooling lane instead of taking tasks out and putting them back, so a task keeps one taskId and one queue entry and the `settle` / `pushDocument` / outbox rules above need no extra case. A handler returns `TaskOutcome` (`runTask`): "skipped" (job already finished) starts no cooldown. A new kind of task gets a case in `laneOf` (its own lane, `delayMs` for the backoff, a new `TaskEffect`) and goes through `scheduler.add`; webhook deliveries are one: a single `webhook` lane for all jobs, capped at `WEBHOOK_CONCURRENCY` (a lane's cap stays stored in the queue until removed, so per-job lanes would leak caps). `release(jobId)` runs when a job's last task settles. Not in the store: there are no reserved time slots (`next_slot_at`, `slots`, `outbox.run_at` are dropped on open).
- `packages/sex/src/engine/jobs/` — `JobStore` + `TaskQueue` interfaces. `SqliteJobStore` (`sqlite.ts`, bun:sqlite) keeps job state; `BunqueueTaskQueue` (`queue.ts`) runs tasks on bunqueue's embedded broker; a lane is a bunqueue group (`groupId`), `capLane` a stored per-group concurrency override (it applies only because the worker passes a default `group.concurrency`), a cooldown the broker's `worker.rateLimitGroup`, called on the `completed` event (not inside the handler, where it re-runs the job). Tasks without a group are served first, then groups in turn; bunqueue `priority` only orders within a group, so it is not used. The redelivery rules are tested by delivering a task twice (`scheduling.test.ts`, `settlement.test.ts`). Both use files under `SEX_DATA_DIR` (`jobs.sqlite`, `queue.sqlite`; `serve` defaults to `$XDG_DATA_HOME/sex`) or `:memory:` without one (tests, one-shot CLI). `packages/sex/src/engine/tasks.ts` dispatches tasks to the crawl/batch/extract handlers. A task interrupted by a crash is redelivered after a restart (bunqueue's startup recovery counts it as an attempt and dead-letters the task at `attempts`, so `BunqueueTaskQueue` sets `attempts: MAX_DELIVERIES` and its worker wrapper swallows handler errors so a throw is not retried; `attempts: 1` meant no redelivery, #75). A task interrupted `MAX_DELIVERIES` times ends in bunqueue's DLQ, and recovery emits no event for that, so `startWorker(handler, onAbandoned)` reads the DLQ once at start (`getDlqAsync`) and passes each task to `abandonTask` (`tasks.ts`), then `removeDlqJobAsync`; an entry is removed only after `abandonTask` returned. `abandonTask` does what the handler's exit would: a page is failed through `taskEffects.failure` and settled, a crawl start or an extract fails the job (#78), so every side effect of a task is claimed once per `(job, taskId, effect)` in the `task_effects` table: `settle`, `pushDocument` (returns whether the document was new; `countCompleted` increments `completed` in the same transaction), `pushError` (`dropFromTotal`: a failed page leaves `total` in the same transaction; `completed` counts stored documents only, never failures), `claimEffect` (the crawl `started` webhook) and `claimSeen` (a page's redirect target: a redelivery that finds the mark it made itself carries on instead of dropping the page). Handlers go through `taskEffects(engine, job, taskId)` in `packages/sex/src/engine/jobs/effects.ts` (`page` / `failure` / `started`), which sends the `page` webhook only for a new document; do not call `pushDocument` or `sendWebhook("page")` from a handler directly. Crawl discovery goes through `store.schedule` (seen, robots-blocked, `scheduled` / `total` / `pending` and one `outbox` row per page task, in one transaction); the task queues its rows and then calls `released`, and a redelivered task queues what its crashed delivery left (`outbox(job, owner)`), under the same taskIds. A duplicate delivery's document bytes are orphans (never indexed, so never read; cut off on open if at the end of a JSONL file).
- `packages/sex/src/engine/jobs/webhook.ts` — webhooks. `sendWebhook(engine, job, event, data?, error?)` (async, never throws; call it through `taskEffects` / `settleTask` / the job's own finish, not for page events directly) builds Firecrawl's payload (`success`, `type: <kind>.<event>`, `id`, `webhookId`, `data`, `metadata`, `error`) and queues a `webhook` task through the scheduler; `deliverWebhook` (run by `runTask`) is one attempt: it claims the `webhook` effect for its taskId (a task delivered twice POSTs once), POSTs through `safeFetch` (10 s) with `X-Firecrawl-Signature: sha256=<hmac>` when `SEX_WEBHOOK_SECRET` is set (`node:crypto`; the schema rejects that header in a request's `headers`), and on a network error, 5xx, 408 or 429 queues the next attempt as a new task (new taskId, same payload and `webhookId`, `delayMs` = 5 s doubling, `WEBHOOK_MAX_ATTEMPTS` = 5). A webhook task is not part of the job's `pending` and never settles. A crash after the claim loses that attempt (no resend). A failed page (`taskEffects.failure`) sends `page` with `success: false`; extract sends `started` (`taskEffects.started`, so extract tasks have a taskId), `completed` (`data: [result]`) and `failed`.
- `packages/sex/src/engine/jobs/documents.ts` — `DocumentLog`: where scraped documents' bytes go (`append` / `read` / `drop`, plus optional `truncate` for logs that append in place). `FsDocumentLog` (one append-only `<jobId>.jsonl` per job, default under `<dataDir>/documents`), `S3DocumentLog` (`Bun.S3Client`, one object per document), `MemoryDocumentLog` (no data dir). `createDocumentLog` picks one from `SEX_DOCUMENTS_URL` / `--documents-url` (`s3://bucket/prefix`, `file:///path`). The SQLite `documents` table indexes them (`object`, `offset`, `length`, `chars`); `documentsJson` returns a page as raw JSON texts, which the crawl / batch status routes send without parsing (`outputStructure: "detailed"` with a `ReadableStream` body).
- `packages/core/src/http/server.ts` — `createHttpApp` / `serveHttpApp`: the Hono app for one product's `AppSpec` (router, MCP server, name): Host/Origin checks, CORS, `/health`, `/docs`, MCP over HTTP at `/mcp`. `packages/core/src/http/procedures.ts` — `procedureBase<E>()` (AppError → oRPC error) and `coreRoutes` (`/v2/scrape`, `/v2/search`). `packages/sex/src/http/router.ts` adds sex's procedures to `coreRoutes`; the team endpoints (`/v2/concurrency-check`, `/v2/team/queue-status`) read `TaskQueue.counts()` (bunqueue) and the store, never a counter of their own; `packages/sex/src/http/server.ts` wraps the core app as `createApp` / `serveHttp`.
- `scrapeUpload` (`packages/core/src/scrape.ts`) is `scrapeUrl` for a file the caller sent: the same `scrapeInner` with `internal.upload` as the response (no `safeFetch`, no browser), a synthetic `file:///<name>` URL so the name picks the converter, `sourceURL` = the file name. `POST /v2/parse` (`packages/sex/src/http/router.ts`, sex only) takes `multipart/form-data` (`file` + `options` JSON string) through oRPC's own `File` input; the size cap is `SEX_MAX_BODY_BYTES` (checked on `File.size`; `serveHttpApp` also sets Bun's `maxRequestBodySize` to it plus 1 MiB).
- `packages/core/src/mcp/tools.ts` — `registerFetchAndSearch` (`web_fetch`, `web_search`), `guard`, `ToolMessageError`. `packages/sex/src/mcp/server.ts` adds the other `web_*` tools (map, crawl / status / cancel, batch scrape / status, extract / status; `async: true` on extract returns the id) and renames the six that firecrawl-mcp also has when `SEX_MCP_TOOL_NAMES=firecrawl` (`mcpToolNames`; `registerFetchAndSearch` takes the names); there is no stdio transport, and MCP modules must not import from `http/`.
- `packages/core/src/schemas.ts` — Zod schemas mirroring Firecrawl v2 for scrape and search (OpenAPI + MCP params); `packages/sex/src/schemas.ts` re-exports them and adds map / crawl / batch / extract / jobs.
- `packages/core/test/helpers.ts` — fixture site, mock SearXNG, `startCountingProxy` (a forward proxy that records requests; a public IP literal such as `93.184.216.34` passes the SSRF check without DNS and the proxy delivers it to a local fixture), `testCoreEngine()` / `testCoreConfig()`; `packages/sex/test/helpers.ts` re-exports them and adds the mock LLM and `testEngine()`. Tests of core modules live in `packages/core/test`.

## Gotchas

- Never pass JS *functions* to `page.evaluate`: Bun's bundler can rename globals like `document` inside them. Pass strings.
- Browser and LLM are optional; features needing them must fail with `browserRequired()` / `llmRequired()` (501).
- Both builds pass `--root packages`: the extract worker is an extra entrypoint, and `extract-pool.ts` finds it in the binary at `<root>/core/src/extract-worker.ts`.
- here-docs is `--external` in the bundle. `packages/sex/scripts/build.ts` embeds its runtime closure for the target platform file by file (`with { type: "file" }`, via a generated `packages/sex/src/cli.embedded.gen.ts` that registers them and then imports `cli.ts`). At runtime `packages/sex/src/engine/docs.ts` extracts the files once to `$XDG_CACHE_HOME/sex/docs-<digest>` (native libraries load only from real files) and imports here-docs from there; `--compile-autoload-package-json` is required for that on-disk resolution. From source it imports `here-docs` from node_modules. It resolves to TypeScript source through the `bun` export condition (`customConditions` in tsconfig); there is no `dist/` in a Bun install.
- Content-type checks for "is this markup" use `MARKUP_TYPE` from `packages/core/src/net.ts`; a bare `/xml/` also matches OOXML office documents.
- The SearXNG binary comes from the per-platform optional dependency `@searxng-js/<os>-<cpu>` (linux-x64 glibc ≥ 2.35, darwin-arm64, win32-x64 only); `bun build --compile` embeds the target's one through the package's literal imports, and it is unpacked to `$XDG_CACHE_HOME/searxng-js/` at runtime. Elsewhere (linux-arm64, musl) `SEX_SEARXNG_URL` is required. `@searxng-js/searxng` is pinned to an exact version. `testEngine()` / `testCoreEngine()` default `searxngUrl` to a dead port so tests never start a real SearXNG; tests that run `serve` as a subprocess must set `SEX_SEARXNG_URL`.
- `dist/sex` embeds Lightpanda: the release pinned by version and per-platform SHA-256 in `packages/sex/scripts/lightpanda.ts` (linux x64/arm64 glibc ≥ 2.35, macOS x64/arm64; none for Windows or musl). `packages/sex/scripts/build.ts` downloads it into `$XDG_CACHE_HOME/sex-build`, checks the hash and embeds it zstd-compressed; `findLightpanda` in `packages/sex/src/engine/browser.ts` uses an explicit `--lightpanda-path` first, then the embedded one (decompressed once to `$XDG_CACHE_HOME/sex/lightpanda-<version>-<hash>/`), then PATH. Compose has no browser service, but the binary being present enables nothing: `SEX_LIGHTPANDA` decides. Same for here-docs and `SEX_DOCS`.
- Screenshots (format and action) and the pdf action are deliberately unsupported (501), even with a browser.
- User-supplied URLs must only be fetched through `safeFetch` / `assertPublicUrl` (or the browser with its `requestGuard`), never with a bare `fetch`.
- Logs go to stderr only (stdout carries CLI output).
- Document seqs are assigned when the index row is written, after `append` resolves, so object names must never depend on the seq. Bytes are written before the index row: on open the store cuts unindexed tails (`truncate`, only for jobs that exist); index rows past the end of a JSONL file are dropped on open. Reads never change the index: documents whose bytes are missing or not a whole JSON object are left out of the page with a warning, since on S3 that can be transient or a configuration problem. Documents are deleted only by job id, for jobs the store deleted itself: the sweep writes a tombstone (`dropped_jobs`) in the same transaction as the job's deletion and removes it after `DocumentLog.drop` succeeds; every sweep (one runs on open) retries the remaining tombstones. Never delete documents because they were found in the bucket or directory, which may be shared, and never delete job rows without a tombstone.
- bunqueue's embedded broker is a process-wide singleton bound to one `dataPath`: every `BunqueueTaskQueue` in a process must use the same path (tests use `:memory:` only; the durability test runs `serve` as a subprocess). Always pass `dataPath` explicitly, or bunqueue reads generic env vars like `DATA_PATH` / `SQLITE_PATH`. `shutdownManager()` runs when the last queue closes. bunqueue is pinned to an exact version (it releases very often); bump it deliberately and rerun the job tests.
- `SEX_REDIS_URL` / `SEX_REDIS_PREFIX` are rejected with `CONFIG_INVALID` (Redis/BullMQ and the `worker` command were removed).
- There is no frontend. HTTP endpoints are oRPC procedures (`coreRoutes` plus `packages/sex/src/http/router.ts`) mounted in Hono; don't add a frontend bundle or a second routing layer.
- When settings change, update the README env table and this Layout in the same change.

## Commands

- Use Bun, not Node: `bun <file>`, `bun install`, `bun run <script>`, `bun test`, `bun check` (type check, not `tsc`).
- `bun install`
- `bun run verify` — `bun check && bun run lint && bun test`
- `bun run format` — Biome write
- Opt-in suites: `SEX_TEST_SEARXNG=1` (the real SearXNG binary, optionally `SEX_TEST_SEARXNG_PATH`; `bun test packages/core/test/searxng.test.ts`), `SEX_TEST_CDP_URL=http://127.0.0.1:9222` (browser tests against a running CDP browser), `SEX_TEST_LIGHTPANDA_PATH=/path/to/lightpanda` (the same browser tests through the spawn path, plus child process lifecycle tests; `bun test packages/sex/test/browser.test.ts`) and `SEX_TEST_S3_URL=s3://bucket/prefix` with `S3_ENDPOINT` / `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` / `S3_REGION` (the job store contract and durability tests with documents on S3; `bun test packages/sex/test/store-contract.test.ts packages/sex/test/durability.test.ts`). Locally and in CI an S3 server is SeaweedFS: `docker run -d -p 127.0.0.1:8333:8333 -e AWS_ACCESS_KEY_ID=sex -e AWS_SECRET_ACCESS_KEY=sex-secret chrislusf/seaweedfs:4.48 server -s3 -dir=/data -ip.bind=0.0.0.0` (MinIO no longer publishes images on Docker Hub); buckets are created on first write.
- `packages/sex/test/docs.test.ts` runs the real here-docs engines (installed as a dependency) against fixtures in `packages/sex/test/fixtures/`; it skips itself where here-docs cannot start (e.g. Intel macOS).
- `bun run build` (`packages/sex/scripts/build.ts`) — single binary at `dist/sex`, SearXNG, Lightpanda and here-docs embedded (the first build downloads Lightpanda); `--target bun-<os>-<arch>` for other platforms whose packages are installed
- `bun run build:lite` (`packages/sex-lite/scripts/build.ts`) — `dist/sex-lite`, SearXNG embedded. `docker build --target lite .` builds its image; the default target is sex.
- `bun run dev` / `bun run dev:lite` — run sex / sex-lite from source.
